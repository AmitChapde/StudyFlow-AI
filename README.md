# AI Workspace

AI Workspace is a goal-driven productivity application built with Next.js, MongoDB, JWT authentication, and Google Gemini. Users can create workspaces, define goals, generate actionable tasks with AI, manage task priority and due dates, and track completion insights from a workspace dashboard.

## Features

### Authentication

- User signup with name, email, and password.
- Password hashing with `bcryptjs`.
- Login with email and password.
- JWT-based session token stored in an HTTP-only cookie.
- Protected dashboard and workspace routes through Next.js middleware.
- Logout endpoint that clears the auth cookie.

### Workspaces

- Create personal workspaces.
- View all workspaces available to the logged-in user.
- Each workspace stores its owner through `createdBy`.
- Workspace membership is already modeled through `WorkspaceMember`.
- Workspace creator is automatically added as an `ADMIN`.
- Membership roles currently support `ADMIN` and `MEMBER`, giving the project a clear extension point for RBAC.

### Goals

- Create goals inside a workspace.
- Each goal belongs to a workspace and the user who created it.
- Creating a goal triggers AI task generation.

### AI Integration

- Uses `@google/generative-ai`.
- Uses the Gemini `gemini-2.5-flash` model.
- Generates 4 to 6 realistic tasks from a user goal.
- Expands an individual task into smaller concrete steps.
- AI responses are parsed as JSON and normalized by the backend service.

### Task Management

- Tasks are generated from goals and stored in MongoDB.
- Task status supports `TODO` and `DONE`.
- Tasks can be marked complete or reopened.
- Tasks can be edited.
- Tasks can be deleted.
- Tasks support descriptions generated by AI.
- Tasks support due dates.
- Tasks support priority levels: `LOW`, `MEDIUM`, and `HIGH`.
- Due date labels include overdue, due today, due tomorrow, and due in N days.
- Overdue tasks are visually highlighted.
- Tasks can be expanded with AI into smaller actionable steps.

### Dashboard and Insights

- Main dashboard for workspace creation and workspace listing.
- Workspace page for goal creation and task management.
- Workspace insights page with:
  - Total tasks
  - Completed tasks
  - Pending tasks
  - Completion rate
  - Task distribution chart using Recharts

### UI and Developer Experience

- App Router architecture with Next.js.
- TypeScript throughout the application.
- Tailwind CSS v4.
- shadcn-style UI primitives.
- Radix UI components.
- Lucide icons.
- Sonner dependency available for toast notifications.
- Mongoose models for MongoDB collections.

## Getting Started

### Prerequisites

Install the following before running the project:

- Node.js 20 or newer
- npm
- MongoDB database, local or hosted
- Google Gemini API key

### Installation

Clone the repository and install dependencies:

```bash
npm install
```

Create a local environment file:

```bash
cp .env.example .env.local
```

 As per `.env.example` , create `.env.local` manually with the variables below.

```env
MONGODB_URI=your_mongodb_connection_string
JWT_SECRET=your_jwt_secret
GEMINI_API_KEY=your_gemini_api_key
PORT=3000
```

Do not commit real secrets. If real credentials were ever committed or shared, rotate them immediately.

### Run the Development Server

```bash
npm run dev
```

Open the app at:

```text
http://localhost:3000
```

### Build for Production

```bash
npm run build
npm run start
```

### Lint

```bash
npm run lint
```

### Test

```bash
npm test
```

The Jest suite covers authentication token verification, due-date labels, task service updates/deletes, workspace creation, workspace membership defaults, workspace listing, and workspace lookup behavior. External services and database writes are mocked so tests run safely without changing application data.

| --- | --- | --- |
| `MONGODB_URI` | Yes | MongoDB connection string used by Mongoose. |
| `JWT_SECRET` | Yes | Secret used to sign and verify JWT auth tokens. |
| `GEMINI_API_KEY` | Yes | API key for Google Gemini task generation and task expansion. |
| `PORT` | Optional | Port used by the local server. Defaults to `3000` for Next.js. |

## Application Flow

1. A user signs up with name, email, and password.
2. The password is hashed before storage.
3. The user logs in and receives an HTTP-only JWT cookie.
4. Middleware protects dashboard and workspace routes.
5. The user creates a workspace.
6. The creator is added as an `ADMIN` workspace member.
7. The user creates a goal inside the workspace.
8. Gemini generates task suggestions from the goal.
9. Generated tasks are stored in MongoDB.
10. The user updates task status, priority, due date, or title.
11. The dashboard aggregates task completion stats for the workspace.

## API Routes

### Auth

| Method | Route | Description |
| --- | --- | --- |
| `POST` | `/api/auth/signup` | Create a new user account. |
| `POST` | `/api/auth/login` | Authenticate a user and set the JWT cookie. |
| `POST` | `/api/auth/logout` | Clear the auth cookie. |

### Workspaces

| Method | Route | Description |
| --- | --- | --- |
| `GET` | `/api/workspaces` | Get workspaces for the current user. |
| `POST` | `/api/workspaces` | Create a workspace. |
| `GET` | `/api/workspaces/[id]` | Get a workspace by id. |
| `GET` | `/api/workspaces/[id]/stats` | Get task stats for a workspace. |

### Goals

| Method | Route | Description |
| --- | --- | --- |
| `POST` | `/api/goals` | Create a goal and generate tasks with AI. |

### Tasks

| Method | Route | Description |
| --- | --- | --- |
| `GET` | `/api/tasks?workspaceId=...` | Get tasks for a workspace. |
| `PATCH` | `/api/tasks/[taskId]` | Update task status, title, description, due date, or priority. |
| `DELETE` | `/api/tasks/[taskId]` | Delete a task. |
| `POST` | `/api/tasks/expand` | Expand a task into smaller AI-generated steps. |

### Health

| Method | Route | Description |
| --- | --- | --- |
| `GET` | `/api/health` | Health check endpoint. |

## RBAC Extension Scope

The project already includes the foundation for role-based access control:

- `WorkspaceMember` stores a user, workspace, and role.
- `createWorkspace` automatically adds the creator as `ADMIN`.
- `getUserWorkspaces` returns workspaces through membership records.
- Roles are currently defined as `ADMIN` and `MEMBER`.


## Development Notes

- Database connection is centralized in `lib/db.ts`.
- JWT verification is handled in `lib/auth.ts`.
- Current-user lookup is handled in `lib/getCurrentUser.ts`.
- Frontend API calls use `lib/api.ts`.
- AI prompts and Gemini calls are isolated in `services/ai.service.ts`.
- Task mutation logic is isolated in `services/task.service.ts`.
- Workspace creation and membership setup are handled in `services/workspace.service.ts`.
- Due-date label styling lives in `lib/task-utils.ts`.
